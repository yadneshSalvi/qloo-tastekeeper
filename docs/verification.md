## Database and provider boundaries

Real PostgreSQL regressions cover concurrent invitation claims, tenant/client/delegate isolation and forced non-bypass RLS, idempotency conflicts, atomic request allowances, revocation during computation and release, correction effects, delayed outbox events, disabled clients and expiry, immutable histories, current catalog authority, and stale-worker fencing.

Durable client tests expire a five-minute credential and resume through its still-authorized opaque browser handle. A separate Node-process restart test reuses the same signed cookie and recovers its last brief, run membership, and saved selections. Revocation, disconnect, and client substitution deny subsequent access. Four additional asset tests verify that HTML contains SHA-256 versions of its exact served JavaScript/CSS bytes and that a new deployment changes those URLs, so a normal reload bypasses an older browser cache entry.

Deletion tests check that context erasure removes private reference revisions and captured input/result payloads immediately, workspace erasure removes dependent records and sessions, and expiry maintenance physically purges guest workspaces. Ordinary runtime callers cannot bypass immutable-record triggers merely by setting the erasure flag.

Mocked live-pipeline tests use actual PostgreSQL plus a deny-by-default provider transport. They verify exactly one Qloo/two OpenAI HTTP reservations, unchanged Qloo order, omission of unmapped/unreturned candidates, and absence of private reference names/UUIDs from both model requests. Revocation committed during the first model tool step prevents the second HTTP request and every final release receipt. The facts-only AI tool contract is checked with exact public spans and a deterministic renderer, including the partial-description case that failed the earlier free-prose contract. Public coverage counts survive the client projection and older stored runs recover the count without another provider call. These are contract/policy tests, not claims that a mocked provider delivered a live recommendation.

Bounded HTTP tests accept a synthetic 188,066-byte five-movie envelope and exactly 1 MiB of Qloo data, cancel streams that cross the limit even without a trustworthy Content-Length, and enforce a shared deadline through stalled response bodies. Search also uses the 1 MiB limit; OpenAI remains at 128 KiB. No provider UUID or private raw response is committed as a fixture.

Search tests verify concurrent duplicate requests share one job and one paid-attempt reservation, alternatives retain identity differentiators, browser output contains opaque candidate IDs instead of canonical provider UUIDs, foreign owners cannot read or confirm results, and confirmation appends a new signal/revision without widening existing grants. A failed provider attempt remains reserved and is never automatically retried.

## Browser verification

The actual owner/client flows approve a gift, claim the single-use invitation in a separate client host, save a choice, preview and cancel a correction, explicitly apply it, verify changed authored ordering and unchanged other context, inspect owner-only evidence, and revoke access. Subsequent result reads, requests, and selections are denied. Personal film and outing clients have their own catalogs, credentials, interfaces, constraints, and selections.

Isolated browser tests check host-only cookie separation, public-only client payloads, no server credential crossover, dialog focus/Escape restoration, mobile navigation trapping, touch targets, horizontal overflow, and axe WCAG A/AA rules in the tested states. Search-result and confirmation dialogs were checked at both viewport sizes. No violations were reported in those tested states; this is not a comprehensive accessibility or screen-reader audit.

Screenshots from current test runs are generated under ignored `.artifacts/owner` and `.artifacts/clients`. Intercepted states are explicitly named `synthetic-*` under `.artifacts/ui-states`; they must not be presented as evidence of a live provider response. Traces and failure artifacts remain private because they may contain temporary demo invitation material.

## Limits of this evidence

A local TLS handshake test verifies the default hostname check, acceptance under an explicitly trusted unique CA, and rejection with an unrelated CA even in `instance-ca` mode. Hosted negative-CA verification remains a separate deployment check.

No participant preference study, large-scale load test, production identity verification, key-rotation/backup-restore drill, merchant availability check, purchase, or booking is claimed. Technical authorization correctness and real Qloo ranking observations are separate from evidence that a particular person prefers the suggestions.
